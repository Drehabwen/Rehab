## 1. 信息架构（现状）

```
深色侧栏（240 / 80px 可折叠）        主内容区
├─ 品牌：青跃智衡康复工作台            PageHeader（eyebrow / 标题 / 描述 / summary 徽标 / 右侧动作）
├─ 接诊中心  (ClipboardList)          ├─ 接诊中心：4 个统计卡 → 搜索条 → 任务卡列表（空态）
├─ 评估中心  (Activity)               ├─ 评估中心：3 个统计卡 + 评估模块卡 → 筛选 → 任务卡列表（空态）
├─ 报告中心  (FileText)               ├─ 报告中心：报告筛选（患者/接诊/准备度三卡）→ 模块结果 → 洞察 → 侧栏归档
├─ 数据中心  (Database)               ├─ 数据中心：4 统计卡 → 历史接诊表 + 模块覆盖 + 数据说明
├─ ───────────                        └─ 选中患者后：PatientHeaderBar（姓名/头像/接诊次数/返回/设置）
└─ 系统设置  (Settings)                   工作区 = 插件渲染（体态/ROM/语音/量表）
                                         底部 WorkspaceToolbar（工具切换）
```

关键交互：**患者上下文只在「评估中心」内有效**；切到报告/数据中心会重置 assessment stage；患者头只在评估中心出现。

## 2. 实际设计语言（从代码反推，不是文档）

| 维度 | 实际值 | 备注 |
|---|---|---|
| 主色 | `#0D9488`（teal-600，`antey-primary`） | 侧栏 logo、主按钮、激活点 |
| 强调色 | 蓝 `#3B82F6`、紫 violet、绿 emerald、琥珀 amber、红 rose | 每类卡片挑一种，缺统一映射 |
| 背景 | 侧栏 `slate-900`；内容区白 + `mesh-gradient`（几乎看不出） | 深色壳 + 浅色内容 |
| 字体 | 系统中文（index.html 未引字体） | 无品牌字形 |
| 字号 | Tailwind 被改写：xs=10px / sm=11px / base=14px；同时大量 `text-[9px]/[10px]/[11px]/[28px]` 任意值 | 层级不统一 |
| 字重 | 实际以 `font-medium/semibold` 为主 | 文档写 `font-black`，已废弃 |
| 圆角 | 卡片 `rounded-2xl`(24px)、按钮 `rounded-xl`(16px) | 文档写 `rounded-[2.5rem]`，不一致 |
| 阴影 | 自定义 `shadow-[0_10px_28px_rgba(15,23,42,0.05)]` 这类硬编码 | 没有 elevation token |
| 间距 | 页面 `space-y-5`、卡片 `p-5/p-6` | 大留白，1600 宽屏利用率偏低 |

**文档冲突**：`DESIGN_SYSTEM.md` 要求"禁止硬编码 Tailwind、必须用 `uiStyles` 常量"，`UI_DESIGN_GUIDE.md`（2026-02）写 teal + font-black + 超大圆角；而实际代码基本是硬编码 slate/white。三套说法并存。

## 3. 组件与复用

- `components/ui`：`Card / Button`（有 variant/padding）、`Tag`
- `components/layout`：`PageHeader / PatientHeaderBar / StatePanel`
- `components/workflow`：`AssessmentCard / VisitCard / StatusTag` + 本期新增 `ModuleResultCard / ModuleReportSection`
- `hub/components`：`HubSidebar / PatientToolbox / NexusReportCenter / ReportDetailDialogs / ProgressComparison …`
- 插件：`vision3 / rom / medvoice`（现已内核插件化，贡献 `assessment.tools / workspace / result.renderers / report.sections`）

复用是有的，但同类卡片存在 3 种写法（`bento-card`、`Card`、手写 `rounded-2xl border`），视觉一致性靠人记。

## 4. 逐页观察

**接诊中心**：4 个统计卡（0/0/0/0）+ 搜索条 + 空态。首屏信息价值低——统计卡在空数据时纯占位；「新建患者」在 header 和空态各出现一次。

**评估中心**：3 个统计卡 + 「评估模块」卡（现在由插件渲染，验证通过）+ 筛选 + 空态。模块卡是"入口"，但点了没有跳转（当前 tile 只传 onOpenTool，未接导航）。

**报告中心**：三张筛选卡（患者/接诊/准备度）里下拉框占满卡片但内容稀疏；准备度里「体态/脊柱/ROM/语音/量表」是标签却长得像按钮；主按钮「生成综合报告」用 emerald，与主色 teal 冲突；页面动作 3 个平铺，缺主次。

**数据中心**：4 统计卡 + 历史表（空）+ 模块覆盖 + 数据说明。说明文案很长，占了右下整块；表格空态没有引导。

**系统设置**：弹层形式，内容偏"数据设置"（备份/导入导出），命名为"系统设置"过大。

## 5. 问题清单（按影响排序）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **按功能分栏，不按患者主线** | 侧栏 4 中心并列；患者头只在评估中心 | 康复师一天的工作是"跟着患者走"，每切页丢上下文 |
| 2 | **设计系统三套说法** | DESIGN_SYSTEM / UI_DESIGN_GUIDE / 实际代码 | 新人写出来的东西一定不一致 |
| 3 | 字号/间距/阴影硬编码 | 大量 `text-[10px]`、`shadow-[0_10px_28px_…]` | 改一处要全局搜 |
| 4 | 空态占比过大、统计卡全 0 无意义 | 截图 1/2/4 | 首屏像"没做完" |
| 5 | 颜色语义混乱 | teal 主色 + emerald 主按钮 + 每卡不同 accent | 用户分不清"主操作" |
| 6 | 可访问性缺失 | `AssessmentCard` 的导出/删除仅 `title` 无 `aria-label`；`text-slate-400` 作正文 | 键盘/读屏不可用 |
| 7 | 响应式断点缺口 | 侧栏 `hidden md:flex`，移动端无导航 | 平板/手机上不可用 |
| 8 | 重复文案与重复入口 | eyebrow `患者 -> 接诊 -> 评估 -> 报告` 每页都有；新建患者入口 2 处 | 视觉噪音 |
| 9 | 假交互 | 报告准备度标签像按钮不可点；评估模块 tile 当前不可跳转 | 用户会点、会困惑 |
| 10 | 卡片套卡片 | 报告中心 Card > Card > inner Card | 层级过深、padding 浪费 |

## 6. 改造方向（建议按 A→B→C）

### A. 收敛设计系统（约 1 周，先做）
1. `src/styles/tokens.css`：颜色（品牌/语义/表面）、字号 scale、间距、圆角、阴影 elevation、动效时长
2. `components/ui` 扩展：`Button`（primary/secondary/ghost/danger + size）、`Card`（elevation 三档）、`Tag`、`EmptyState`、`StatCard`、`PageHeader` 收敛为一个实现
3. 清理文档：`DESIGN_SYSTEM.md` + `UI_DESIGN_GUIDE.md` 合并成一份，写"实际在用的"
4. 验收：全站 grep 不再出现 `text-[1xpx]` 任意值；按钮/卡片只走组件

### B. 信息架构改造（1–2 周，与工作台化一起）
1. 侧栏改为 **今日 / 患者 / 报告 / 数据 / 设置**（评估不再是"中心"，而是患者详情里的动作）
2. 全局患者上下文：选中患者在顶部固定一条 PatientBar，任何页面都不丢
3. 首页 = 今日工作台（待接诊/待评估/待复测/待确认报告），空态给"新建患者/导入早筛"
4. 验收：从今日工作台点一个待办 → 进入患者 → 完成评估 → 回到今日，全程不用回首页

### C. 视觉升级（约 1 周，最后做）
1. 品牌色体系（青跃 teal 主色 + 单一强调色），语义色固定映射（蓝=信息、琥珀=待办、红=风险、绿=完成）
2. 深色壳 + 浅色工作区的对比拉开（侧栏加噪点/渐变），内容区用 elevation 而非边框
3. 空态插画 + 一句话行动；数据可视化用统一图表规范
4. 验收：截图对比，主操作按钮一眼可辨
