# 青跃智衡 · 移动端 v1 PRD（数据入口）

> 版本：v0.2（草案）
> 分支：`reform/minimal-loop`
> 核心判断：**移动端是数据入口，桌面端是回顾与科研。**

## 1. 背景

康复科的诊疗数据每天都在产生（接诊、评估、文书），但存在两个断点：

1. **录入摩擦**：桌面系统需要专门坐下来操作，门诊/查房节奏里用不起来
2. **数据不沉淀**：文书用完即弃，无法形成纵向队列，科研链路无原料

移动端 v1 只解决一件事：**让康复师在真实工作节奏里愿意、且能够完成录入。**

## 2. 双端分工

| | 移动端（v1 重点） | 桌面端 |
|---|---|---|
| 角色 | 采集端 | 管理与研究端 |
| 用户 | 一线康复师 | 康复师/医生（下班后、周末回顾） |
| 时机 | 门诊中、床旁、走廊，单手 | 一天结束、周末，坐定 |
| 任务 | 接诊登记、量表、语音问诊、出报告 | 回顾接诊、查看趋势、科室管理、Galen 科研 |
| 目标 | **90 秒录完一例** | 复盘 + 产出（报告/论文） |
| 不做 | 统计分析、论文 | 高频录入 |

**关键原则**：桌面端不做"录入优化"，移动端不做"分析功能"。

## 2.5 首日体验（新用户空状态）

> 新科室第一天打开时没有任何数据。这一屏决定用户会不会有第二天。

| 状态 | 页面表现 | 行动 |
|---|---|---|
| 无患者 | 空状态卡片：「今天还没有接诊」+ 三个入口 | ① 新建第一位患者 ② 导入历史名单（Excel/CSV）③ 载入 3 个演示患者试用 |
| 有患者无评估 | 列表显示"待评估"，顶部提示 | 「开始接诊」直达量表 |
| 首次进入 | 一页 15 秒引导（3 张图：接诊→量表→报告） | 可跳过，不重复出现 |

**导入历史名单**（决定科研冷启动）：
- 支持列：姓名、性别、年龄、最近一次量表分（可选）
- 导入后立即生成可用患者档案与 RehabID
- 失败行给出明确原因（缺列 / 格式错误 / 重复）

**原则**：首日必须让用户 3 分钟内完成"创建 → 录入 → 看到报告"的完整闭环，否则视为流失。

## 3. 用户与场景

**主用户：康复师（一线）**
- 门诊 15–20 位患者/半天，单例 10–20 分钟
- 手机在手，单手持握，另一只手做评估
- 诉求：别增加时间；交班/家属沟通要一张能看的报告

**次用户：医生/科室负责人（桌面端）**
- 下班后/周末回看当日接诊、异常患者、趋势变化
- 诉求：快速回顾、发现漏评、为科研积累

## 4. 核心用户流程

### 4.1 移动端主流程（Happy Path，≤90 秒）

```
打开 PWA（已登录）
  → 今日接诊列表（7 位待处理）
  → 「开始接诊」（新建或继续）
     ├ 新患者：输入姓名（可选）→ 自动 RehabID
     └ 老患者：自动带出上次量表值
  → 量表（点选 10 项，实时总分，上次预填）
  → 语音问诊（录音 30s → 转写 → 结构化要点）
  → 保存 → 自动生成一页报告
  → 「发送给家属」/「继续下一位」
  → 数据自动回传（成功：✓ 已同步；失败：进入重试队列）
```

### 4.2 异常流程

| 场景 | 处理 |
|---|---|
| 断网 | 本地暂存，显示"待同步"，恢复后自动重试 |
| 录音中断（来电/切后台） | 草稿自动保存，回到页面可继续或重录 |
| 上传失败 | 明确错误文案 + 手动重试按钮，不静默 |
| 量表未填完就保存 | 必填校验拦截，高亮未填项 |
| 语音转写不准 | 降级为「录音 + 关键要点点选」，转写仅作参考；允许手动纠正要点 |
| 患者重复创建 | 按姓名+性别+年龄提示可能重复，允许继续 |

### 4.3 桌面端流程（v1 仅保留最小回顾）

```
打开桌面端 → 今日/本周接诊概览
  → 某患者详情：纵向评分趋势、语音摘要、历史报告
  → 导出研究批次（JSONL）→ Galen 导入 → 队列/选题/论文
```

## 4.4 语音降级策略（v1 关键）

语音是 v1 最重、最不可控的模块。设计原则：**结构化结果不依赖转写准确率。**

| 层级 | 内容 | 不依赖的条件 |
|---|---|---|
| L1 必保 | 录音文件 + 时长 + 人工点选的关键要点（疼痛部位、诱因、时长、既往治疗） | 完全不依赖转写 |
| L2 增强 | 自动转写文本（可编辑） | 依赖转写质量 |
| L3 未来 | 自动结构化摘要 | 依赖模型与数据量 |

v1 交付 L1 + L2；转写失败或不准时，用户仍能通过点选完成病史采集。转写文本始终可编辑（不只是 P1）。

## 5. 功能范围

### P0（v1 必须）
1. 登录与设备记住状态
2. 患者新建 / 复用（RehabID 自动生成）
3. 今日接诊列表与状态（待评估 / 可报告 / 待同步）
4. 量表：点选、上次值预填、实时总分、必填校验
5. 语音问诊：录音、上传转写、结构化要点、重录
6. 一页报告：摘要生成、复制/分享、完成接诊
7. 同步：本地 IndexedDB、失败重试队列、断网可用
8. 导出：研究数据批次（JSONL + SHA-256）
9. PWA：可安装、竖屏锁定、图标、启动页
10. 草稿自动保存

### P1（v1.1）
- 患者搜索、历史记录查看
- 报告模板可选
- 语音转写编辑修正

### Out of Scope（v1 明确不做）
体态/ROM 摄像头评估 · 家属端 · 权限与角色 · 统计报表 · 论文生成 · 多科室 · 微信生态

## 6. 页面（四屏）

1. **今日接诊**：今日待办数、已完成/待报告统计、患者任务列表（下一步直达）、底部「开始接诊」
2. **量表**：进度条、上次值提示、0–5 点选、实时总分、较上次变化、保存并出报告
3. **语音问诊**：大麦克风、计时、波形、实时转写、结束录音
4. **报告**：患者摘要、报告内容、同步状态、发送家属、继续下一位

## 7. 数据与流转

```
Patient(rehabId, 性别, 年龄, 本地姓名不上传)
  └ Visit(开始/结束, 状态)
      ├ Scale(量表类型, 分值, 总分)
      ├ Voice(录音时长, 转写, 结构化要点)
      └ Report(摘要, 生成时间)

SyncBatch(状态, 重试次数, 时间戳) → POST 院内后端 → 桌面端/Galen 读取
```

**传输约束**：客户端字段白名单，姓名等直接标识不上传；同步接口留 `SyncTarget` 抽象（HTTP / 本地 / 院内网关）。

## 8. 指标（v1 只看四个）

| 指标 | 目标 |
|---|---|
| 单例录入时长 | ≤ 90 秒 |
| 周活跃康复师 | ≥ 3 人 |
| **次日继续使用率** | ≥ 60%（第二天仍打开并完成 ≥1 例） |
| 量表完成率 | ≥ 80% |
| **数据完整率** | ≥ 90%（每例含必需模块与报告） |
| 数据回传成功率 | ≥ 99%（含重试；埋点记录成功/失败/重试次数） |

**埋点定义**（必须落表，否则指标不可观测）：`sync_attempt`(visitId, 结果, 重试次数, 时间)、`entry_duration`(visitId, 秒)、`report_generated`(visitId)。

## 8.5 桌面端 v1 明确范围

| 页面 | 内容 | 验收 |
|---|---|---|
| 概览 | 今日/本周接诊数、待评估、待同步、异常提示 | 打开 2 秒内可见数字 |
| 患者详情 | 纵向评分趋势、语音要点、历史报告 | 任一患者可查看完整时间线 |
| 接诊详情 | 单次接诊的量表/语音/报告 | 可回看并补写报告 |
| 数据导出 | 研究批次（JSONL + SHA-256） | Galen 可导入 |

明确不做：录入优化、批量编辑、权限管理、统计报表。

## 9. 里程碑

- **M1（本周）**：PWA 壳 + 今日接诊 + 量表，可跑通一例
- **M2（两周）**：语音问诊 + 报告 + 同步队列
- **M3（一月）**：导出批次 + 桌面端最小回顾 + 试点复盘

## 10. 开放问题

1. 语音转写：浏览器 Web Speech（免费、离线差）vs 云端（准、有成本）——v1 按"降级策略"可先不定
2. 登录方式：手机号 / 科室码 / 扫码登录
3. 桌面端 v1 是否保留"接诊录入"入口（建议保留但默认引导到手机）
