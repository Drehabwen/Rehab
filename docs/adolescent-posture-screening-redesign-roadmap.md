# 青少年体态筛查监控中心改版方案与开发路线图

## 0. 文档目的

本文档用于把 [adolescent-posture-screening-center-spec.md](/C:/Users/DORAT/Desktop/sport%20rehab/Rehab-V3.1/docs/adolescent-posture-screening-center-spec.md) 转换为可执行的产品改版方案、功能清单和开发线路图。

适用对象：

- 产品负责人
- 设计负责人
- 前端开发
- 后端开发
- 测试与实施人员

本文档回答三个问题：

1. 产品怎么改版
2. 先做哪些功能
3. 开发应该按什么顺序推进

## 1. 改版总目标

本次改版的核心不是“做更多功能”，而是把现有能力收敛成一条清晰主线：

> 从“泛运动康复工具集合”改为“面向机构场景的青少年体态筛查、风险分层、复测跟踪平台”。

### 1.1 改版目标

- 收敛首页与导航，让用户一进系统就知道它是筛查监控中心
- 重构主流程，让“筛查 -> 风险 -> 报告 -> 复测”成为默认闭环
- 把机构、班级、学生档案引入一级结构
- 降低次要模块的干扰，保留但下沉 ROM、训练建议、治疗计划等能力
- 为后端权限、数据模型和组织结构改造留出清晰接口边界

### 1.2 改版不做什么

- 不在本阶段扩展更多病种
- 不把语音问诊做成主流程
- 不优先做复杂 AI 生成式治疗报告
- 不继续强化“个人用户自测工具”的叙事

## 2. 现状问题

基于当前仓库结构，主要问题如下：

- 首页与模块命名仍带有明显的康复平台色彩
- 工作流更偏“单次评估”，缺少机构化筛查与复测闭环
- 学生档案、组织结构、批量筛查任务不是一级主对象
- 报告能力存在，但没有完全围绕“风险分层和跟踪管理”组织
- 权限和数据模型尚未进入真正的机构级产品形态

这意味着当前最需要的是结构重排，不是继续叠加新页面。

## 3. 改版后的信息架构

### 3.1 一级导航

目标态一级导航建议固定为以下 6 项：

- `首页`
- `筛查工作台`
- `学生档案`
- `报告中心`
- `预警复测`
- `机构管理`

### 3.2 导航说明

| 模块 | 作用 | 目标用户 |
|---|---|---|
| 首页 | 今日工作、统计概览、异常提醒 | 全角色 |
| 筛查工作台 | 快速筛查、标准筛查、现场采集 | 执行员、复核人员 |
| 学生档案 | 学生历史记录、趋势、标签 | 执行员、复核人员、管理员 |
| 报告中心 | 个人报告、班级汇总、导出 | 复核人员、管理员 |
| 预警复测 | 高风险名单、复测计划、追踪动作 | 复核人员、管理员 |
| 机构管理 | 组织、账号、授权、阈值、设备 | 管理员 |

### 3.3 二级结构建议

#### 首页

- 今日待筛查
- 已完成筛查
- 异常人数
- 待复测人数
- 快捷入口
- 机构概览趋势

#### 筛查工作台

- 快速筛查
- 标准筛查
- 学生检索/扫码入场
- 本次任务清单
- 采集完成状态

#### 学生档案

- 学生基本信息
- 历次筛查记录
- 风险标签
- 趋势变化
- 附件与报告
- 跟进记录

#### 报告中心

- 个人筛查报告
- 班级汇总报告
- 机构周期报告
- 导出记录

#### 预警复测

- 高风险学生
- 待复测
- 超期未复测
- 跟进处理状态

#### 机构管理

- 组织结构
- 班级/队伍
- 角色账号
- 设备与站点
- 监护人授权状态
- 指标阈值配置

## 4. 页面级改版方案

## 4.1 首页改版

### 当前问题

- 更像工具入口集合
- 缺少机构运营视角
- 缺少筛查任务驱动

### 改版目标

首页 SHOULD 成为“今天要做什么”和“哪里有风险”的入口，而不是“有哪些模块”的列表。

### 首页结构

1. 顶部总览卡片
2. 今日任务区
3. 风险预警区
4. 快捷启动区
5. 趋势与统计区

### 首页关键卡片

- 今日待筛查学生数
- 今日已完成数
- 异常待复核数
- 待复测数
- 本周筛查完成率

### 首页快捷入口

- 开始快速筛查
- 开始标准筛查
- 打开待复测列表
- 查看今日报告

## 4.2 筛查工作台改版

### 当前问题

- 更偏单次评估页面
- 缺少任务上下文
- 缺少学生维度的现场流转

### 改版目标

筛查工作台 MUST 变成“现场执行页面”，让执行员可以快速完成一批学生的筛查。

### 页面结构

1. 左侧任务与学生列表
2. 中部筛查入口与采集界面
3. 右侧当前结果摘要
4. 底部会话状态与下一人操作

### 支持的两条主流

- 快速筛查流：选学生 -> 选视角 -> 拍摄 -> 风险结果 -> 完成
- 标准筛查流：选学生 -> 三视角采集 -> 结果汇总 -> 提交复核

## 4.3 学生档案改版

### 当前问题

- 历史结果可能存在，但没有形成产品主对象
- 缺少完整的纵向跟踪视角

### 改版目标

学生档案 MUST 成为产品核心页面之一。

### 页面结构

- 基本信息
- 最近一次筛查结论
- 风险等级与标签
- 历史趋势
- 报告列表
- 复测与跟进记录

### 档案页必须回答的问题

- 这个学生当前风险等级是什么
- 过去是否持续异常
- 是否需要复测
- 是否已经被处理

## 4.4 报告中心改版

### 改版目标

报告中心不再只是“导出内容页面”，而是“可被检索、筛选、汇总和追踪”的业务中心。

### 页面结构

- 个人报告列表
- 按班级/队伍汇总
- 按时间周期汇总
- 导出操作与历史记录

### 报告类型

- 个人筛查报告
- 班级筛查汇总
- 学校/机构周报月报

## 4.5 预警复测改版

### 改版目标

把“发现问题后怎么办”做成显式模块。

### 页面结构

- 高风险学生
- 待复测学生
- 复测逾期学生
- 已处理/未处理状态
- 跟进动作记录

### 关键操作

- 标记复测
- 标记已通知
- 标记已复核
- 标记已完成跟进

## 4.6 机构管理改版

### 改版目标

让系统具备机构级落地能力，而不是停留在单机工具层。

### 页面结构

- 机构与校区
- 班级/队伍
- 用户角色
- 设备与站点
- 授权与隐私配置
- 指标阈值与模板

## 6. 模块去留建议

### 6.1 保留并上升为主线

- Vision3 筛查能力
- 报告能力
- 趋势与数据看板
- 角色权限体系

### 6.2 保留但降级

- ROM 评估
- MedVoice
- 治疗计划生成
- 泛康复建议内容

### 6.3 暂缓继续投入

- 非筛查主线的复杂 AI 交互
- 个人用户导向页面
- 与机构批量场景无关的实验性页面

## 7. 开发路线图

## Phase 0：基础收敛

### 目标

先统一口径和结构，避免继续在旧叙事上开发。

### 任务

- 固定产品命名与术语
- 确定一级导航
- 清点当前页面映射关系
- 标记保留、降级、废弃模块
- 明确 `Rehab-V3.1` 为主仓库

### 交付物

- 新导航草图
- 页面映射表
- 模块去留表

## Phase 1：MVP 可用版本

### 目标

完成最小闭环：筛查、风险、档案、报告、复测。

### 任务

- 首页改版
- 筛查工作台改版
- 学生档案页
- 风险分层模型接入
- 个人报告模板改版
- 待复测列表页

### 验收标准

- 执行员可以完成快速筛查和标准筛查
- 单个学生可以形成完整筛查档案
- 每次筛查都有风险等级
- 可以查看并筛选待复测对象

## Phase 2：机构化版本

### 目标

让产品从“单人使用”进入“机构运营”阶段。

### 任务

- 组织结构模型接入
- 班级/队伍管理
- 批量筛查任务
- 报告中心汇总能力
- 机构看板
- 权限与审计升级

### 验收标准

- 支持按机构/班级查看数据
- 支持批量任务驱动筛查
- 支持导出班级或机构汇总结果

## Phase 3：增强版本

### 目标

做持续监控与干预协同，不再只停留在筛查结果展示。

### 任务

- 高风险预警规则
- 家长通知流程
- 跟进动作记录
- 干预建议闭环
- 二级专项评估模块接入

### 验收标准

- 能看见异常后的后续动作
- 能管理复测与跟踪状态
- 能区分筛查结果和干预建议

## 8. 技术开发顺序

建议按以下顺序推进，而不是前端后端完全分离：

1. 先做领域模型与术语统一
2. 再做导航和页面结构改版
3. 同步补学生档案、筛查结果、风险等级的数据结构
4. 再做机构组织、批量任务与汇总
5. 最后接入家长视图、预警和干预闭环

### 8.1 前端优先改造点

- 统一导航层
- 首页布局
- 筛查工作台流程拆分
- 学生档案页
- 报告中心列表化

### 8.2 后端优先改造点

- 真实鉴权模型
- 学生与组织数据模型
- 筛查会话模型
- 风险分层字段
- 报告与复测状态模型

### 8.3 测试优先改造点

- 权限越权测试
- 筛查流程契约测试
- 报告生成契约测试
- 风险分层判定测试
- 学生档案读写测试

## 11. 本轮开发决策规则

后续所有需求进入开发前，必须先判断：

- 它是否服务“筛查、监控、复测、机构管理”主线
- 它是否提升机构场景效率
- 它是否会增加不必要的康复平台叙事
- 它是否要求新的权限、隐私或审计处理

如果答案不清楚，该需求不应直接进入开发。

## 12. 推荐的下一步执行动作

按最小阻力路径，建议立刻执行以下动作：

1. 先出页面映射表，把现有页面归类为保留、降级、废弃
2. 先画新一级导航和首页框架
3. 先定义学生档案、筛查会话、风险等级三张核心数据结构
4. 再开始改筛查工作台和报告中心

这比直接改视觉样式更有效。
