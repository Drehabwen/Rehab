# 最小闭环产品定义（改革分支基线）

> 目标：让康复师**今天就能用起来**，并在不增加负担的前提下持续沉淀数据。
> 一句话：日常只做最少的事，数据自动变成科研资产。

## 1. 核心判断

- 产品护城河 = 科室长期积累的纵向队列数据，不是功能数量
- 一切设计服从一个目标：**低摩擦地把数据留下来**
- 功能齐全但没人用 = 零数据 = 科研链路无法启动

## 2. 最小日常路径（≤90 秒/例）

| 步骤 | 内容 | 目标 |
|---|---|---|
| 1 | 接诊登记（患者 + 本次接诊） | 1 次点击进入，自动生成 RehabID |
| 2 | 量表（必需） | 上次值预填，键盘可完成，≤60 秒 |
| 3 | 保存 → 报告 | 即时生成，可用于沟通/归档 |

**体态 / ROM / 语音问诊：保留能力，按需使用，不阻塞任何流程。**

## 3. 功能砍留表

| 能力 | 定位 | 是否阻塞报告 |
|---|---|---|
| 接诊登记 | 日常必须 | 否 |
| 量表评估 | 日常必须 | 是（必需模块） |
| 体态评估（摄像头） | 增值 | 否 |
| ROM 评估 | 增值 | 否 |
| 语音问诊 | 增值 | 否 |
| 报告生成 | 日常必须 | — |
| 研究数据导出 → Galen | 后台自动 | — |
| 队列/选题/论文初稿 | 月度/季度产出 | — |

## 4. 冷启动设计（决定生死）

1. **历史数据导入**：支持 Excel/CSV 导入旧病例（患者 + 既有评分）
2. **小样本也能出稿**：病例报告 / case series 模板，3–5 例即可成文
3. **月度科室数据简报**（自动）：本月接诊数、评估完成率、平均改善 Δ、随访完整率，附一句"再积累 X 例可支撑队列研究"

## 5. 数据资产承诺（对医院的核心卖点）

- **归属**：数据归科室/医院所有
- **可导出**：结构化 JSONL/CSV 全量导出，带 SHA-256 校验
- **可迁移**：不锁定产品，导出格式有公开契约文档
- **可审计**：去标识字段白名单、传输批次校验
- **离线可用**：单机可运行，不依赖云

## 6. 试点验收（两周 / 1 个科室）

| 指标 | 目标 |
|---|---|
| 单例录入时长 | ≤ 90 秒 |
| 周活跃康复师 | ≥ 3 人 |
| 评估完成率（量表） | ≥ 80% |
| 出报告数 | ≥ 20 份/两周 |
| 数据导出成功 | 100% |

**判据**：三项达标继续投入，两项未达回炉砍功能，不靠猜测。

## 7. 里程碑

- M1（本周）：90 秒录入路径 + 报告门禁闭环
- M2（两周）：Excel 历史导入 + 月度数据简报
- M3（一月）：Galen 端月度队列分析自动化 + 试点复盘
